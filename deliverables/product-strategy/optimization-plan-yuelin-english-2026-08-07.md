## 0. TL;DR（执行摘要）

悦琳英语当前产品完成度 56%（P0=92% / P1=20% / P2=20%），核心问题是 **mock 假反馈使产品停留在"玩具"阶段**——随机发音评估、硬编码错误诊断、mock 对话记录让家长端所有价值归零。本轮优化以 **"从玩具到工具"** 为主线：**P0 立即修复 6 项关键缺陷**（错误处理、数据安全、语音死循环、完成页成就感缺失、选课引导、中文兜底），**P1 接入 Azure 真实发音评估 + DeepSeek 真实记录生成**（核心差异化价值），**P2 轻度游戏化 + 儿童友好化**（体验增强）。P1 完成后，产品完成度预计从 56% 跃升至 ~75%，家长可首次看到真实、个性化的学习反馈。

## 1. 产品目标

本轮优化聚焦三个清晰、正交的目标：

### 目标 1：从"假反馈"到"真诊断"——核心价值闭环

**当前状态**：发音评估随机打分（62-74/82-100 区间波动）、诊断建议 4 条通用文案所有记录相同。[数析数据分析]  
**目标状态**：Azure 真发音评估逐词评分 + DeepSeek 真实跟读记录 → 家长端展示个性化薄弱项 → 下次复习智能推荐。  
**衡量指标**：发音评估词级别准确率 ≥ 90%（与人工评估对比）；诊断建议去重率 ≥ 80%（同一学生连续 3 次课不出现完全相同建议）。

### 目标 2：从"能跑"到"可靠"——工程质量底线

**当前状态**：后端 API 错误覆盖率仅 6.7%、单 JSON 文件无原子写入、无超时机制、Safari/iPad 兼容性未验证。[数析数据分析]  
**目标状态**：所有 API endpoint 100% try/catch 覆盖、数据写入原子化 + 每日备份、语音识别 3 次空识别自动兜底、Safari/iPad 端到端可用。  
**衡量指标**：后端 API 错误覆盖率 100%；连续 7 天零数据丢失；Safari 上全流程可走通。

### 目标 3：从"能用"到"想用"——儿童体验升级

**当前状态**：选课页无操作引导、完成页只有固定鼓励语、语音失败无提示、PIN 锁定页成人化文案。[瑞思用户研究]  
**目标状态**：选课页"单选即开始"交互、完成页本课成果可视化、语音失败三级兜底、全局儿童友好化文案。  
**衡量指标**：悦琳单次独立完成率 ≥ 80%（无需爸爸中途介入）；完成页"告诉爸爸"按钮点击率 ≥ 60%。

## 2. 用户故事

### 故事 1：悦琳独立完成一节口语课（P0 + P1）

> **场景**：周六上午，悦琳打开 iPad，输入 PIN 码进入。选课页一目了然——"上周学的 Unit 3 At the Farm"高亮显示。她点了一下就开始。跟读时，读得好的词显示绿色 ✅，读得不好的显示黄色 ⚠️，她知道自己哪个词需要再练。有一次她沉默了 8 秒，AI 温柔地说"Try saying 'cow' — like this: /kaʊ/"。25 分钟后，完成页展示 🐮 4/5 ⭐⭐⭐⭐，她开心地跑去告诉爸爸。

**关联需求**：P0-3 选课页操作引导、P0-4 完成页成果展示、P0-5 语音超时兜底、P1-1 Azure 发音评估真接入、P1-4 会话前麦克风测试

### 故事 2：爸爸首次看到真实的进步记录（P1）

> **场景**：爸爸下班后打开悦琳英语仪表盘。这次不一样了——不再是千篇一律的"需要更多练习"，而是："悦琳本周薄弱音素：/θ/（three）、/æ/（cat）。建议下次课前重点练习 Unit 3 动物词汇发音。"下方还有一张小图：本周发音准确率从 72% 提升到 78%。爸爸截图发给了妈妈。

**关联需求**：P1-2 DeepSeek 真实记录生成、P1-3 仪表盘增强

### 故事 3：悦琳第一次主动"再来一节课"（P2）

> **场景**：悦琳完成一节课后，看到自己获得了 🌟 连续打卡 3 天徽章，页面底部还显示了"下次预习：Unit 4 — My Family 新单词"。她点了一下预习卡片，AI 用中文简单介绍了下节课要学的内容。5 分钟后她跑去找爸爸："爸爸，明天还能继续学吗？"

**关联需求**：P2-1 轻量游戏化、P2-2 仪表盘复习预告、P2-4 教材模板库扩展

### 故事 4：爸爸放心让悦琳独立使用（P0）

> **场景**：以前悦琳每次卡住都喊"爸爸！它不动了！"。现在——连续 3 次没识别到声音时，AI 主动说"我没听清，我们试试这个单词好吗？"并展示示范发音。如果还是不行，页面出现"跳过这个单词 →"按钮。爸爸在客厅听到的不再是求助，而是悦琳自己跟读的声音。

**关联需求**：P0-5 语音超时兜底、P0-6 mock 阶段中文翻译兜底、P1-4 会话前麦克风测试

### 故事 5：爸爸准备下节课只需要 2 分钟（P1 部分 + P2）

> **场景**：周三晚上，爸爸上传了 Unit 4 的 PDF 教案。系统自动解析出核心词汇和句型，锚定到会话主题。爸爸只需确认 3 个选项（"本周重点：动物词汇" / "难度：Level 2" / "时长：25分钟"），点击保存。不再需要手动编写对话脚本。

**关联需求**：P1 教案解析增强（本次部分覆盖）、P2-4 教材模板库扩展

## 6. 优化需求池

### 6.1 P0 — 立即修复（本周）

#### P0-1：后端 API 全局 try/catch 补全

| 属性 | 内容 |
|------|------|
| **当前问题** | 后端 API 错误覆盖率仅 6.7%，未捕获异常直接 500 崩溃 [数析] |
| **需求描述** | 所有 FastAPI endpoint 添加全局异常处理中间件 + 逐路由 try/catch，错误日志写入文件 |
| **验收标准** | |

**Given/When/Then：**

- **Given** 任意 API endpoint 在运行时抛出未预期异常  
- **When** 异常发生  
- **Then** 返回统一 JSON 错误格式 `{"error": true, "code": "INTERNAL_ERROR", "message": "...", "request_id": "..."}`，HTTP 状态码 500，异常堆栈写入 `logs/error.log`，不泄露敏感信息到前端

- **Given** 文件读写操作因磁盘满或权限不足失败  
- **When** 写入操作失败  
- **Then** 返回 `STORAGE_ERROR` 错误码，不静默丢失数据

**检查清单：**

- [ ] 添加 FastAPI 全局 exception_handler 中间件
- [ ] 所有现有路由逐文件审查，补充 try/catch（预估 12-15 个 endpoint）
- [ ] 统一错误响应 schema：`{error, code, message, request_id}`
- [ ] 错误日志写入 `logs/error.log`，按日期轮转
- [ ] `request_id` 使用 uuid4，方便前端排查
- [ ] 生产环境不返回 traceback 到前端

| **估算工作量** | 4-6 小时 |

---

#### P0-2：数据持久化原子写入 + 备份

| 属性 | 内容 |
|------|------|
| **当前问题** | 单 JSON 文件直接写，并发写数据竞争，进程崩溃数据全丢 [数析] |
| **需求描述** | 写入改为"写临时文件 → 原子 rename"；每日自动备份到 `backups/` 目录；启动时检测数据文件完整性 |
| **验收标准** | |

**Given/When/Then：**

- **Given** 两个并发请求同时写入同一会话数据  
- **When** 写入操作同时发生  
- **Then** 后完成的写入使用临时文件 + `os.rename` 原子替换，不会出现数据交错损坏

- **Given** 进程在写入过程中被 kill -9  
- **When** 写入中断后重启服务  
- **Then** 数据文件保持上一次完整状态，不出现空文件或截断 JSON

- **Given** 每日凌晨 3:00  
- **When** 备份定时任务触发  
- **Then** `backups/data-YYYY-MM-DD.json` 创建成功，保留最近 7 天备份

**检查清单：**

- [ ] 所有 `json.dump` 改为写临时文件 + `os.replace`
- [ ] 添加 `fcntl.flock`（Linux）/ `msvcrt.locking`（Windows）文件锁
- [ ] 添加 cron / schedule 每日备份任务
- [ ] 启动时 `json.load` 捕获 JSONDecodeError，fallback 到最新备份
- [ ] 添加数据完整性校验（必填字段检查）

| **估算工作量** | 3-4 小时 |

#### P0-5：语音识别超时兜底机制

| 属性 | 内容 |
|------|------|
| **当前问题** | 连续空识别时 scheduleListen 持续重试，无超时无提示无跳过，孩子只能喊爸爸 [瑞思建议3] |
| **需求描述** | 三级兜底：10 秒沉默 → AI 示范发音；连续 3 次空识别 → AI 引导提示；累计 5 次 → 自动跳过并标记 |
| **验收标准** | |

**Given/When/Then：**

- **Given** 悦琳进入跟读环节，系统等待语音输入  
- **When** 10 秒内无任何语音输入（speechStart 未触发）  
- **Then** AI 播放："Try saying 'cow' — like this: /kaʊ/"（TTS 或浏览器语音），同时高亮示范文本

- **Given** 系统已连续 3 次收到空识别结果（speechEnd 触发但 transcript 为空）  
- **When** 第 3 次空识别发生  
- **Then** AI 播放："I didn't catch that. Let's try the next word."，自动跳到下一个跟读词

- **Given** 同一会话中累计 5 次超时/空识别事件  
- **When** 第 5 次事件触发  
- **Then** 当前练习词标记为 `skipped`，自动继续下一词，会话结束后在记录中显示为"需课后复习"

**检查清单：**

- [ ] 前端 `scheduleListen` 增加 `maxSilenceTimeout: 10000ms`
- [ ] 空识别计数器 `consecutiveEmptyResults`，达到 3 后触发兜底
- [ ] 累计跳过计数器 `totalSkippedInSession`，达到 5 后标记会话
- [ ] 每个兜底事件写入会话日志（用于 P1-2 真实记录生成）
- [ ] 跳过按钮始终可见但不鼓励使用（小字灰色，放在底部）

|--------|------|----------|
| 数据库迁移（JSON → SQLite/PostgreSQL） | 当前数据量极小（单用户），JSON 原子写入修复后足够用 3-6 个月 [数析] | P0-2 原子写入 + 备份 |
| Azure 语音 TTS（文本转语音） | 浏览器内置 TTS 对单用户场景足够，Azure TTS 每月有费用 | 浏览器 `speechSynthesis` API |
| 前端框架迁移（SPA → React/Vue） | 当前原生 JS hash 路由满足需求，重构成本极高 | 保持现有技术栈 |
| Safari SpeechRecognition polyfill | Safari 不支持 Web Speech API，P1 直接用 Azure ASR SDK 替代 | P1-3 Azure ASR SDK |
| 实时音频流处理 | 当前"录音→上传→识别"模式对逐句跟读足够，实时流复杂度高 | 保持现有模式 |

### 体验层面暂不做的

| 非目标 | 原因 | 预计版本 |
|--------|------|----------|
| 动画角色/IP 形象全程陪伴 | 开发周期长，9 岁儿童不需要过度幼稚化 [瑞思] | v3.5 |
| 积分商城/实物奖励 | 过度游戏化偏离学习目标 | 暂不规划 |
| 家长端微信小程序 | Web 端优先，单用户场景不需要 | v4.0 |
| 多语言支持（中英以外） | 当前仅需中英双语 | 暂不规划 |

## 10. 待确认问题

以下问题需要产品总监（爸爸）确认后，方可锁定最终开发计划：

### 技术和资源

1. **Azure 账号与配额**：Azure Speech Services 的免费层（F0）每月 5 小时音频，是否需要升级到标准层（S0）？预计月费用？[P1-1 阻塞项]
2. **DeepSeek API 额度**：当前 API Key 的每分钟/每天调用限制是多少？单次诊断预计消耗 ~2K tokens，每日 1-2 次调用，是否在免费额度内？[P1-2 阻塞项]
3. **iPad 型号**：悦琳使用的 iPad 型号和 iOS 版本？Safari 版本？需确认对 Azure Speech SDK 和 getUserMedia 的兼容性。[P1-3、P1-4 依赖]

### 产品方向

4. **游戏化程度**：P2-1 的轻量游戏化（打卡+星级+徽章）是否合适？还是希望更克制（只要打卡）或更丰富（积分+排行榜）？9 岁女生的偏好需要验证。[P2-1 范围确认]
5. **"告诉爸爸"分享方式**：P2-6 的分享卡片，是"复制一段文字发微信"还是"生成一张图片"？前者实现简单但体验一般，后者需要 html2canvas。[P2-6 技术选型]
6. **教材模板优先级**：P2-4 模板库优先覆盖哪套教材？悦琳当前用的教材是？人教版 PEP / 牛津 / 新概念少儿 / 其他？[P2-4 范围确认]

### 体验细节

7. **错误提示语言**：语音兜底（P0-5）和完成页（P0-4）的 AI 提示语，用英文还是中文？建议"指令用英文 + 必要时追加中文解释"的混合策略是否可行？
8. **PIN 重置机制**：悦琳忘记 PIN 时，爸爸如何远程/现场重置？当前是否有重置机制？P2-2 是否需要包含"爸爸解锁"流程？
9. **断签策略**：P2-1 打卡断签后，current streak 归零但 longest streak 保留——这样可以吗？还是连断 2 天给一次"补签"机会？
